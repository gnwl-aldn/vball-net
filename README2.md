# VballNetの使い方とレシーバーの記録手順

## 1. VballNetによるボール座標の記録

### 1.1 ディレクトリの移動

ターミナルで以下を実行する。

```bash
cd ~/volleyball_project/vball-net
```

### 1.2 ボール座標の記録ツールを起動

対象のラリー動画と、VballNetの検出結果が保存されたCSVを指定して実行する。

```bash
uv run src/imgLabel.py \
  --video_path ../clips/【動画ファイル名】.mp4 \
  --csv_path ~/fast-volleyball-tracking-inference/output/【動画ファイル名】/ball.csv
```

**実行例**

```bash
uv run src/imgLabel.py \
  --video_path ../clips/0609_01_rally001.mp4 \
  --csv_path ~/fast-volleyball-tracking-inference/output/0609_01_rally001/ball.csv
```

※ 動画ファイル名とCSVの保存先は、対象のラリーに合わせて変更する。

### 1.3 基本操作

| 操作 | 機能 |
|---|---|
| マウス左クリック | ボールの位置を指定・訂正 |
| マウス中央クリック | ボール座標をクリア |
| `n` | 次のフレームへ進む |
| `p` | 前のフレームへ戻る |
| `f` | 最初のフレームへ移動 |
| `l` | 最後のフレームへ移動 |
| `>` | 36フレーム早送り |
| `<` | 36フレーム早戻し |
| `s` | ここまでの結果をCSVに保存 |
| `e` | 終了 |

### 1.4 ボール座標の記録手順

1. 動画を確認し、ボールが見えているフレームを探す。
2. ボールの位置をクリックして座標を記録する。
3. `n` で次のフレームへ進む。
4. 次のフレームでも同様に、ボールの位置を記録する。
5. 最後まで確認したら、`s` で保存する。
6. `e` で終了する。

### 1.5 状況別の操作

| 動画上の状態 | 操作 |
|---|---|
| ボールが見えており、既存の座標も正しい | そのまま `n` |
| ボールが見えているが、既存の座標がずれている | 左クリックで訂正 → `n` |
| ボールが見えないのに、誤検出の座標が残っている | 中央クリックでクリア → `n` |
| ボールが見えず、座標も正しくクリアされている | そのまま `n` |

**注意：** 座標を修正・削除した場合は、変更を保存するために `s` を実行する。

## 2. レシーバーの記録

### 2.1 記録ファイルの方針

ラリー単位の情報と、レシーブ単位の情報を別々のCSVファイルで管理する。

| ファイル | 役割 |
|---|---|
| `rally_log.csv` | ラリーのメタデータを管理 |
| `receive_log.csv` | ラリー内の各レシーブの情報を管理 |

`receive_log.csv` の `match_id` と `rally_no` を使って、`rally_log.csv` の該当するラリーと紐づける。

### 2.2 receive_log.csv のカラム

| カラム名 | 内容 | 記録例 |
|---|---|---|
| `match_id` | 試合ID | `0609_01` |
| `rally_no` | ラリー番号 | `1` |
| `receive_no` | ラリー内で何回目のレシーブか | `1`, `2`, ... |
| `court_sid` | レシーブしたコート側 | `奥` / `手前` |
| `position` | レシーブした選手のポジション番号 | `1`〜`6` |
| `receive_accuracy_label` | レシーブ精度 | `1`〜`5` |

**記録上のルール**

- `match_id`：試合ごとに設定する。
- `rally_no`：`rally_log.csv` と同じラリー番号を使用する。
- `receive_no`：各ラリーの中で `1` から順番に付ける。
- `court_sid`：奥側か手前側かを記録する。
- `position`：レシーブした選手のポジション番号を記録する。
- `receive_accuracy_label`：以下の5段階基準で評価する。

### 2.3 レシーブ精度の評価基準

| 評価 | 判定基準 |
|---:|---|
| 5 | Aパス：セッターが移動せずにトスできる |
| 4 | Bパス：セッターが1〜2歩移動してトスできる |
| 3 | Cパス：セッターはボールに届くが、クイックやコンビ攻撃が使えない |
| 2 | セッター以外の選手が2段トスを上げる |
| 1 | ボールがつながらず、プレーが継続できない |

※ 実際の記録では、研究内で統一した評価基準を使用する。

### 2.4 レシーブ記録ツールの実行

プロジェクトのルートディレクトリを基準に実行する。

```bash
cd ~/volleyball_project
```

```bash
python3 files/log_receive.py --match_id 0609_01 --rally_no 1 --outdir clips
```

※ `--outdir` はスクリプトの実装に合わせて指定する。出力先が `clips` になること、および既存CSVへの追記方法は、必要に応じてスクリプト内で確認する。

### 2.5 入力例

**1回目のレシーブ**

```text
-- receive #1 --
コート側 [奥/手前]: 奥
ポジション番号 [1/2/3/4/5/6]: 5
レシーブ精度 [1/2/3/4/5]: 3

このラリーに続けてレシーブを記録しますか? [y/n]: y
```

**2回目のレシーブ**

```text
-- receive #2 --
コート側 [奥/手前]: 手前
ポジション番号 [1/2/3/4/5/6]: 5
レシーブ精度 [1/2/3/4/5]: 2

このラリーに続けてレシーブを記録しますか? [y/n]: n
```

`y` を入力すると、同じラリー内の次のレシーブを記録する。すべてのレシーブを記録したら `n` を入力して終了する。

## 3. 作業時のチェックリスト

### ボール座標の記録

- [ ] 対象のラリー動画を指定した
- [ ] 対応する `ball.csv` を指定した
- [ ] ボールが見えるフレームの座標を確認した
- [ ] 誤検出や座標のずれを修正した
- [ ] `s` で保存した

### レシーバーの記録

- [ ] `match_id` が正しい
- [ ] `rally_no` が `rally_log.csv` と一致している
- [ ] 各レシーブの `receive_no` が順番になっている
- [ ] コート側とポジション番号を確認した
- [ ] 統一した評価基準でレシーブ精度を記録した
- [ ] 記録結果が `receive_log.csv` に保存されている

---

## 4. 作業全体の流れ

1. 対象のラリー動画を用意する。
2. VballNetでボールの検出結果を確認・修正する。
3. ボール座標をCSVに保存する。
4. レシーブした選手・コート側・ポジション番号・レシーブ精度を記録する。
5. `rally_log.csv` と `receive_log.csv` の対応関係を確認する。
6. 記録したデータを、今後のレシーブ動作解析に使用する。
